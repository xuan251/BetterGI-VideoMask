> 这里是实现原理、每个功能的取舍、以及踩过的坑。
> 想知道「每个版本改了什么」看 [../CHANGELOG.md](../CHANGELOG.md)；

## 〇、v1.1：在线播放换了内核（重点看这段）

以前在线视频走的是 `player.bilibili.com` 的 **iframe**。跨域的结果是：进度条是估的、拖不动、改不了倍速、抓不到画面、只听得到"播没播"。等于把 B 站播放器整个借来用，代价是所有状态都在墙外面。

现在改成**直链自播**：脚本用 `x/player/playurl`（`platform=html5`）拿到**一整个 mp4 直链**，直接喂给 `<video>`。这条直链实测**不带 Referer 也能访问、支持 Range、还允许跨域读像素**，所以下面这些一口气全回来了：

| 能力 | iframe 时代 | 直链自播 |
| --- | --- | --- |
| 真实进度 / 总时长 | 估算 | ✅ 真实 |
| 拖进度条 | ❌ | ✅ |
| 改倍速 | ❌ | ✅ |
| 抓到画面做分析 | ❌ | ✅ |
| 分P切换 | 靠 `&p=` 参数 | ✅ 侧栏列表（本视频 31 个 P 一眼看全） |

清晰度上限变成 **720P**（html5 接口只给 720P / 360P，可在设置里选）。

**新增：视频跳步自动暂停（v1.6.2 起默认关）。** 判据不是"画面动得快"——实测那玩意儿全是打怪特效，会误判。真正靠谱的是**场景突变**（HSV 直方图距离，正常帧 p50=0.06，换场地直接 >0.5）。所以逻辑是：画面换场地 → 观察 1 秒 → 如果接下来不是在连打，就往回退一点停住，提示你自己走完再按播放。没有 CORS 就自动降级成只播不停，不影响播放。

> 为什么要默认关：主播拉近看宝箱、切镜头看地图、视频内切分镜，这些都算"场景突变"，会被当成跳步停一下。实测误停比该停的多，所以**默认不启用**。想试的人：设置里勾「视频跳步时自动暂停」，或点控制条上的 `析` 按钮临时开关（热键也行）。打怪点暂停是另一套（人工标的），v1.6.10 起也**默认关**（标记点还不全，见下面「零点五」）。

## 零点五、v1.2：打怪点（这一段要自己打怪，播到就停）

> **v1.6.10 起默认关闭。** 标记点还没补齐（30 个分P 里只有一部分标过），默认开着会在没标的地方停不住、
> 在标错的地方乱停。想用：`⚙ → 打怪点到点自动暂停` 打开，或设置里勾「打怪点到点自动暂停」。

"这一段要打怪"是个**只有人能确定**的信息，靠画面猜（敌人血条 / 伤害数字 / 运镜）在 360P 攻略视频上做不可靠，我实测过：帧差会把战斗和冲刺跑图混在一起，光流一致性也分不开。所以改成**人来标一次，机器照着执行**：

- 播到打怪点 → 自动暂停，顶上一行提示「到了：第 8 个宝箱　打完再按播放」
- 进度条上会画出红色小刻度，一眼看到还有几个点没打
- 控制条 `＋怪` 按钮 = 在当前时刻打点；**45 秒内已有点时是"移动"它**，Shift + 点击 = 删除
- 按 `bvid + 分P` 各存一份（存进 BetterGI 的设置里，重启不丢）

### 其余 30 个分P：自动标不出来，原因在下面

我拿全部 31P（6.4 小时、346 个宝箱）跑过一遍，**7 种判据全部失败**：

| 判据 | 结果 |
| --- | --- |
| 帧差 | 战斗与冲刺跑图混在一起，全片 26.6% 算"高动态"，等于没标 |
| 光流一致性 | 360P 下小怪只有几十像素，最大一致性 0.27，分不开 |
| 粉红环 HSV | 5 个已知打怪宝箱只命中 2 个，另误报 5 处 |
| 敌人血条 | 打怪宝箱的指标**反而低于**不打怪的宝箱（方向是反的） |
| 音频 BGM | 正负样本三项特征均值差 <3%，完全重叠 |
| 开箱金光 | 只切出 15 段（应有 19 段），且集中在 2~8 分钟 |
| 场景突变 | 20 分钟 99 个点，平均 12 秒一个，太密 |

**根因：UP 主把打怪过程剪掉了。** 宝箱出现在画面里时怪已经清完，只剩一个解锁好的箱子——所以画面、声音里都不存在"这里要打怪"这个信息。血条那项的反向结果就是最硬的证据：如果视频里有战斗，正样本不可能比负样本还低。

另一个旁证在他的视频简介里，标点分类写着 `星星=可见宝箱(包括怪物守护的宝箱等)`、`牛头=首杀`——**"怪物守护"被并进了普通可见宝箱，他的地图也不单独标**。所以他录的时候没有提示，你到现场才会发现打不开。

### 一个必须补充的前提：上面这些全是在 360P 上测的

查的时候发现 `p2.mp4` 被批量下载的 360P 文件覆盖了，所以我那 7 种判据全部是在 **640×360** 上做的 —— 右上角的编号只有 5 像素高、敌人血条几乎不可见、小怪只有几十像素。这直接解释了为什么它们全都不成立。

换成 **1280×720**（脚本默认就是这个清晰度）之后，同一个编号数字是 **31×49 像素、纯白**，二值化后几乎零噪点，肉眼和程序都一眼能读。所以"读编号"这条路是通的，难的不是读数字，是稳定切段——背景（雪地、天空、灯光）偶尔会混进白色像素，全片切出 70 段而实际只有 19 个宝箱。要准确就得做 0~9 的模板匹配，不是简单的形状比对。

其余判据（血条、光流、粉红环、音频）还没在 720P 上重测，理论上会好转，但"打怪被剪掉"这个根因不会因为分辨率改变。

### 两个暂停判据会打架（v1.3 已修）

场景突变和打怪点是两套独立机制，各有各的冷却（4 秒 / 3 秒），互相不知道对方存在。而打怪点几乎都落在"换场地"的那一刻，于是同一处会停两次：先被跳步检测停，你按播放，1 秒后打怪点又把你按回去。

修法：

- 打怪点触发时，把场景突变的冷却一起推到 8 秒后，并清空正在观察的待判项
- 场景突变要暂停前，先看 ±10 秒内有没有打怪点，有就让给打怪点

### 人声：不是"有声音就跳过"，是"等话说完了再停"

实测这条视频里"有人声"的时间只占 **10%~25%**（大量无声段和纯 BGM），所以最初那版"检测到人声就不暂停"等于把功能关掉了。改成**推迟**：该停的时候如果主播正在讲，先记下来，等这一句说完（或最多 6 秒）再停。

判据是三个一起成立：有能量、300~3000Hz 中频占比过半、3 秒内能量波动系数够大（说话是一个字一个字蹦的，BGM 是平的）。拿不到音频（CORS 污染 / 自动播放限制）会自动关掉，并**把音频直通还原**，不会让视频没声音。设置里可关。

> v1.6.2 起自动暂停默认关，所以人声检测也**跟着不启动**（不再多接管音频图，省一点 CPU）。只有把自动暂停打开、或点 `析` 按钮之后，才会在下次播放时开始分析。

### 关于 CORS：不用管，是通的

实测 CDN 会原样回显请求的 `Origin`（`Access-Control-Allow-Origin: https://example.com`），也就是**允许任何来源跨域读像素**。所以画布抓帧、自动暂停这些都能用。万一哪天改成不给头，脚本会自动去掉 `crossorigin` 重载、关掉画面分析，保证先能看。

### 真要彻底解决，得看游戏侧

比起从视频里预判，**在你走近宝箱的那一刻判断"它是不是被锁着"**更可靠：原神里被怪镇守的宝箱外面有一圈粉色光，这个特征在你给的游戏截图上是量得出来的——有环 21025 像素、无环 277 像素，差 75 倍。检测到就提示一句"这里有怪"，不用管视频里有没有剪掉。

关于"会不会把浮窗自己拍进去"：**拍进去也不影响**。做检测时把浮窗那个矩形挖掉、只在剩余区域找环就行。需要的只是知道浮窗在截图坐标系里的位置和是否 1:1，脚本启动 9 秒后会自动存一张 `debug_capture.png` 并把这几个数写进日志：

```
[体检] 游戏截图 1920x1080　浮窗 16,470 尺寸 360x203　右边界 376 下边界 673
[体检] 已存图 debug_capture.png（img.SaveImage）。打开看一眼：视频浮窗在不在图里？
```

## 一点五、关于 #8「清怪暂停」：用 BGI 的识别，不交给 BGI 打

先说清楚一件事：**不需要把打怪交给 BGI 的自动战斗**，那只是我上一版走错的思路。
正确做法是**用 BetterGI 的识别引擎自己判断有没有怪**，然后我们只负责暂停视频。

### 怎么判断"在战斗"

原神进战斗时，**屏幕上方正中出现敌人名字 + 血条**；那块区域平时是空的。
所以：

```
每 0.7 秒截一次屏 → 裁出上方正中 600×70 → 交给 BGI 的 OCR 读字
                                        ↓
                   读到文字（≥2 个字）= 在打怪 → 暂停视频
                   连续 8 秒读不到 = 战斗结束 → 继续播放
```

### 为什么用 OCR 而不是模板匹配

| | OCR 方案 | 模板方案 |
| --- | --- | --- |
| 要不要准备模板 | **不用** | 要自己裁血条图 |
| 换分辨率/UI 缩放 | **不受影响** | 要重新裁 |
| 打不同的怪 | **都能认**（名字不同但都是"有字"） | 血条样式要一致 |
| 实现 | `RecognitionObject.ocr(x,y,w,h)` | `RecognitionObject.templateMatch(...)` |

我一开始打算让你裁模板，是因为没意识到 OCR 这条路 —— 你说得对，**BGI 的 OCR 直接就能用**。

（补充：BGI 的「自动战斗」内部也是用识别判断有没有怪，但它**没有把"当前是否在战斗"
这个状态开放给 JS 查询**——`dispatcher` 只有"启动任务"的接口。所以只能自己识别，
而我们用它的 OCR 引擎识别，效果是一样的。）

### 怎么开（三步）

1. 配置里勾「检测到战斗自动暂停视频」；
2. **先开着「试运行」**（默认就是开的）：只写日志不暂停，日志会打
   `战斗检测读到：丘丘人 Lv.12`；
3. 确认日志里该出现时出现、不该出现时没有 → 关掉「试运行」，就真的会暂停了。

参数：检测区域 `660,20,600,70`（1080P）、至少读几个字 `2`、战斗结束 `8` 秒后继续。

> 万一你的画质/字体导致 OCR 读不出字，可以切「战斗检测方式 = template」，
> 用侧栏「截」截一张图自己裁血条（见 `assets/combat/怎么用.txt`）。这是兜底，不是必需。

## 二、已经做了的（细节）

### 启动：先黑屏，选了地图才播（v1.6.8）

> ⚠️ **本节是 v1.6.8 的原始设计，已被 v1.6.25 取代**（有观看记录直接续播 + 引导页半透明化）。
> 保留在这里只是为了说明当初为什么不做"一启动就播"。

以前脚本一启动就把配置里那个视频塞进播放器 —— 人还没想好要看哪张地图，画面和声音先上来了，
有时候还接着上次随手点的那一集，看着莫名其妙。

现在启动只有一块黑底白字：

```
        先选一张地图
按 Insert 接住鼠标 → 点左上角 ☰
系列栏里选地图 → 一条龙 → 点一集就播
```

- 点这块黑屏本身 = 打开系列栏（鼠标得先被 `Insert` 接住，否则点击到不了浮窗）；
- 空白态点播放 / 快进没有意义，会提示「先在系列栏里选一个视频」；
- 空白态下进度条和打怪点刻度自动隐藏，不在纯黑背景上留一根线；
- 想恢复老行为（启动就播 `videoUrl` / `videoFile`）：把设置里的 **「启动先黑屏」** 取消勾选。

> 顺手删掉了「没配置视频源就自动播合集第一集」—— 那等于一打开侧栏就自己放，跟"启动别自动播"是同一件事。
> 现在点了哪一集才播哪一集。

### 地区分类（v1.6）：把散在各系列里的「枫丹」收成一类

UP 主的视频是**按内容类型**分系列的：`一条龙全收集`、`宝箱全收集`、`神瞳类全收集`、`世界任务`……每个地区只是各自系列里的**一个条目**。所以想看枫丹的东西，得在四个系列之间来回跳。

v1.6 把这层关系倒过来：把所有系列的条目拉平，从标题里认出「哪个地区」「什么类型」，按地区聚成一个分类。

**怎么用（v1.6.11 起是四级钻取，一层只放一样东西）**

侧栏默认就是这一页：**合集卡片**（至冬 / 挪德卡莱 / 纳塔 / 枫丹 / 须弥 / 稻妻 / 璃月 / 蒙德…），**最新的地图永远排第一**（v1.6.9），每张下面写着「一条龙 4 · 宝箱 6 · 神瞳 1 · 主线 23」这样的构成。

```

...

```

| 操作 | 效果 |
|---|---|
| 点右侧键位，再按一个键 | 换键，**立刻生效**并写回设置（下次启动还是这个键） |
| `Esc` | 取消这次改键 |
| 行尾 `×` | 清空这个键（该动作从此只能点按钮） |
| 恢复默认 | F9 播放 / Insert 缩放 / Alt 按住可操作 / End 登录窗，其余清空 |

几个实现上的坑，写下来免得以后又踩：

- **页面收不到键盘**：BGI 浮窗的 WebView2 虽然浮在最前面，但 `document.hasFocus()` 长期是 `false`，
  页面自己的 `keydown` 拿不到键。所以"按一个键"这件事交给主脚本的全局钩子：
  页面发 `/keycap`，钩子把下一个键吃下来、通过 `/keycap` 回传给面板；
- **改键期间不能顺手触发动作**：动作键 / 缩放 / 登录窗 / 按住 / 方向键这 5 处钩子回调，
  开头都要 `if (captureKey(k)) return;`，连按住的 `keyup` 也要让路（否则松手会切回穿透）；
- **一个键只干一件事**：`hotkeySet` 会先把占着这个键的其它动作清空，再写入，然后
  `disposeHook() + setupHook(true)` 重挂钩子（`quiet=true` 免得把一堆一次性说明再刷一遍日志）；
- **10 秒超时**：主循环里兜底，超时就发 `/keycap {cancel:true}`，不让钩子一直处于吃键状态。

- 收起期间鼠标移上去就能操作（脚本把那 34px 当整块热区），点击条上的按钮正常生效；点条的空白处不会交还鼠标了（v1.6.8 起），只会顺手收起设置面板；

### 鼠标怎么还给游戏（v1.6.8 精简）

| 做法 | 结果 |
| --- | --- |
| 按缩放热键（默认 `Insert`） | 退出缩放模式，鼠标穿透给游戏 |
| 鼠标移开浮窗 / 25 秒没操作 | 自动切回穿透 |

**"单击画面还鼠标"已经在 v1.6.8 删掉了。** 它从 v1.6.5 活到 v1.6.7，判定是「按下到松开移动不超过 3px、
时长小于 0.5 秒」。问题是这个手势跟"点暂停没点中""拖完窗口松手""手抖一下"几乎分不开，
结果常常是：你只想把鼠标挪到按钮上，浮窗自己穿回游戏、当场点不动。现在单击只做一件事 —— 收起 ⚙ 面板。
（如果旧页面还发 `/through`，主脚本只记一条日志，不切穿透。）

### 分辨率自适应（v1.5）

浮窗的坐标原本是绝对像素（比如 `1200,12 360×203`）。1600×900 下贴在右上角，换到 2560×1440 还按原坐标摆，就会跑到画面中间、尺寸也只剩一小块。现在多存一份比例：

```
rx = x / 视口宽    ry = y / 视口高    rw = 宽 / 视口宽    ar = 高 / 宽
```

三条触发路径：

| 场景 | 走哪条 | 效果 |
|---|---|---|
| 切全屏 / 改分辨率后叠层窗口跟着变 | `window.resize`（防抖 160ms） | 按比例还原位置，尺寸按 `rw` 缩放，高度按 `ar` 回推，不变形 |
| 叠层盖住整屏、视口没变，但游戏分辨率变了 | 主脚本每秒 `getGameMetrics()` → `/metric` | 以视口中心为基准缩放（居中窗口全屏正好等价于中心缩放） |
| 关掉脚本、换分辨率、再打开 | `vmLayout.ratio` + `baseVw/baseVh` | 启动时按上次的比例直接摆回去，日志会写"上次 1600×900，这次 2560×1440" |

细节：

- **保持宽高比**：只缩放宽度，高度按上次的 `h/w` 回推，不会因为分辨率不同被拉扁；
- **有上下限**：宽 160 ~ 视口 95%，高 90 ~ 视口 95%，再小的窗口也不会缩到看不见；
- **不叠两层**：视口刚重排过 2.5 秒内，`/metric` 直接忽略，否则同一次切全屏会被缩两次；
- **首次启动仍走右上角**：`needDefault` 只在"压根没存过位置"时生效，不会盖掉用户拖过的位置；
- 开关是 **`fitRes`（分辨率自适应）**，默认开。关掉之后只做边界夹取，不按比例重排。

**已知限制：独占全屏（Exclusive Fullscreen）看不到浮窗。** 那是游戏直接把 GPU 输出切走了，任何普通窗口都会被压住，跟脚本无关。要叠着看，请在游戏里选 **「全屏（窗口模式）/ 无边框」** 或直接窗口化。另外若游戏窗口不是居中摆放，切分辨率后位置会有小幅偏移（没有窗口位置 API 可查），拖一下即可，比例会被记住。

### 进度条拖动（v1.4，v1.6.4 挪到底部）

跟丢了拖一下就能追回去，不用再靠快退键一点点点。

- 进度条在**画面最底下那一条**（v1.6.4 从顶部挪下来的，原来贴着顶部太像窗口边框），
  **按住就能拖**，蓝条跟着手走，条上方浮出时间气泡（如 `08:12`）；
- 控制条（那排按钮）一出来，进度条会自动上移 36px 让位，不会互相压住；
- **松手才真正跳转**，拖动过程中不会来回 seek 卡顿；
- 原本在播就接着播，原本暂停就保持暂停，不会"拖一下就自己动起来"；
- 拖完 1.5 秒内不判跳步、也不判打怪点——否则时间突然跳很远，会被误当成"换场地"，一松手视频就自己停住；
- 条本身只有 3px，靠一层 18px 的透明热区撑开，不然小窗口根本点不中。鼠标搭上去时条会变粗提示"这里能抓"。

**为什么有时拖不动**：这层浮窗平时是"鼠标穿透"的（否则会挡住游戏点击），穿透状态下鼠标事件到不了页面。
所以默认开了一个 **`scrubZone`（进度条热区）**：鼠标移到画面底部这 24px 里，脚本会把穿透临时关掉；移开 900ms 后自动恢复。
其余区域始终穿透，不影响游戏操作。

如果连热区也不好用（鼠标钩子没起来），还有三条后路：

1. **按住 `Alt`**（v1.6.14）：原神里 Alt 本来就是"显示鼠标"，按住它浮窗就收点击，拖条点暂停都行，
   松开自动还回去 —— 这是最顺的一手；
2. 设置里勾 **「鼠标悬停到视频上才可拖动」**（`hoverMode`）——整个画面都能抓，移开自动穿透；
3. 或者打开 **「启用键盘热键」**，给 `hkToggleInteractive` 自己填一个键（默认空着；**别填 F9** ——
   那颗已经给播放/暂停了，撞了后面填的那个会自动禁用）。

- **「当前」标题条**：只在第④层（点进某一集）出现，一行 `当前 P4 · 【原神一条龙全收集】至冬7.0…`，
  超出省略、**点一下展开全文**。前三层不挂它，也不挂分P 列表（不再上下分屏）；
- 分P / 视频列表每行只占一行（悬停看全文）；第④层的分P 会撑满整块侧栏，一屏十几个 P；
- **关掉侧栏再打开 = 直接回到正在看的那一集**（第④层），页面上不知道位置时会问主脚本；
- 侧栏底部的 BV 号输入框已在 v1.6.7 删除。

实测真数据：一条龙全收集 21 集、宝箱全收集 31 集、特产全收集 62 集、世界任务合集 727 集。

## 四、SESSDATA（字幕/方向提示需要，可选）

B 站的 AI 字幕接口**匿名返回空**（我实测过），必须带登录态。填法：

1. 浏览器登录 B 站；
2. F12 → 应用/存储 → Cookie → `bilibili.com` → 找到 **SESSDATA**，复制它的值；
3. 粘到脚本配置的「B站 SESSDATA」里。

⚠️ 注意事项：

- SESSDATA **就是你的登录凭证**，等于账号密码，别发给别人；
- 它只保存在本机 BetterGI 的配置组 json 里，不会上传到任何地方；
- 想收回：B 站 → 设置 → 安全 → 退出所有设备，旧的 SESSDATA 立即失效。

**为什么不用「登录按钮」的那个登录态？** 因为脚本侧的 `http.request` 和 WebView 不共享 Cookie，
所以只能把 SESSDATA 直接交给脚本用。

## 五、在线播放与清晰度

### 能不能跟浏览器共用登录？**不能**
WebView2 和 Edge/Chrome 是两个独立浏览器配置，Cookie 不互通，这是硬限制。

### 侧栏「登录」按钮（v1.6.5 起有热键兜底）
会在 BGI 的 WebView 里开一个 B 站窗口让你登录（控制条 ⚙ → 登录，或侧栏里的「登录」）。
**能不能保持、清晰度会不会提升，需要你实测**（取决于 BGI 的 WebView 数据目录是否保留）。

**登录窗是全屏独立窗口，会把浮窗整个盖住 —— 侧栏按钮点不到。** 所以：

- 按 **`End`** 开、再按一下关（热键可改，见 `hkLogin`）；
- 关掉时自动 `reload` 视频，应用新的登录态；
- 忘了关也没事：开着超过 5 分钟会自动关闭，免得游戏一直进不去。

### 为什么不自己写播放器播 B 站流
**实测走不通**：

```
B站 CDN 直链   不带 Referer → 403
              Referer 换成别的站 → 403
              Referer 换成 bilibili → 通
```

`<video>` 标签禁止设置 Referer → 反盗链堵死。所以只能嵌官方播放器（`player.bilibili.com`）。

## 六、缓冲优化

在线模式用**双 iframe 预载**：

```
你在看 A（正在播）
  ↓ F3 快进
后台偷偷加载 B（新时间点），A 继续播
  ↓ B 加载完 + 再等 900ms 拉流
切到 B，A 释放
```

快进不会立刻黑屏，等新的好了再切；期间显示「缓冲中…」。

## 七、热键（默认，可改）

### 先说清楚一个坑：浮窗是浏览器内核，F12 / F5 抢不过它

BGI 的浮窗本质上是个 **WebView2（Edge 内核）**，它自带一整套浏览器快捷键，而 BGI 的
键盘钩子**只能听见按键、吞不掉**。所以同一个键会被两边同时处理：

| 键 | 浮窗那边会干什么 | 后果 |
| --- | --- | --- |
| `F12` / `Ctrl+Shift+I` | 打开开发者工具 | DevTools 窗口弹出来，挡在游戏上 |
| `F5` / `Ctrl+R` | 刷新页面 | **视频从头开始，播放进度归零** |
| `F3` / `Ctrl+F` | 弹出查找框 | 一个没用的查找条挡住画面 |
| `F1` / `F6` / `F7` / `F10` / `F11` | 帮助 / 地址栏 / 光标浏览 / 菜单栏 / 全屏 | 行为不可控 |

v1.6.1 的处理办法：

- **缩放模式默认从 `F12` 改成 `Insert`**
- 你在设置里填了 `F12`、`F5` 这类键，启动时也会**自动换成安全键**并打一行日志
  （`F12→Insert`，`F1/F3/F5/F6/F7/F10/F11→F9`）
- 页面里另外拦掉了 `F3`、`Ctrl+F/P/U/S/O`、`Ctrl+Shift+I/J/C` 和右键菜单
  （F12、F5 是浏览器级命令，页面拦不住，只能靠换键）

#### 到底哪些键「不冲突」：三层都要避开

一个键能不能用来做热键，得同时躲开三家人：

| 谁 | 抢了哪些键 |
| --- | --- |
| 浮窗内置浏览器（WebView2） | `F12` `F5` `F3` `F1` `F6` `F7` `F10` `F11`，以及 `Ctrl+R/F/P/U/S/O`、`Ctrl+Shift+I/J/C` |
| **原神自己**（取自本机 `keyBindingsConfig`） | `W A S D` `E Q R F V Z T X P B C M J Y U G L O`、`1`~`5`、**`F1`~`F8`**（冒险之证/联机/祈愿/纪行/活动/设置/尘歌壶/星之归还）、`Tab` `Esc` `Enter` `空格`、左 `Shift` / 左 `Ctrl` / 左 `Alt`、鼠标左中右键、`/?` |
| BGI 本体 | `F11` = 启停（全局注册）、`↑` `↓` = 挂起/取消任务 |

所以真正干净的只有这些：

| 键 | 状态 |
| --- | --- |
| `Insert` | ✅ 当前缩放热键，最稳 |
| `End` | ✅ 当前登录窗热键 |
| `Home` | ✅ 干净 |
| `Pause` | ✅ 干净（部分键盘没这颗键） |
| `F9` | ✅ **唯一干净的 F 键**：原神只用 F1~F8，BGI 用 F11，浏览器不抢 F9 —— 现在是**播放/暂停的默认键** |
| `6` `7` `8` `9` `0` | ✅ 原神只绑 1~5 切人，6~0 空着 |
| `H` `I` `K` `N` | ✅ 原神默认没绑（你改过键位的话先看游戏里的设置） |
| 小键盘 `0`~`9` | ⚠️ 理论空着，但钩子上报的键名不一定是 `num0`，填了没反应就看日志里「键盘上报的键名」那几行 |

**别用**：`F1`~`F8`（会顺手打开游戏面板）、`F10`（浏览器菜单）、`F11`（BGI 自己启停）、
`F12`（DevTools）、`F5`（刷新，**播放进度直接归零**）、`↑` `↓`（BGI 的挂起/取消，页面自己还拿它调音量）、
以及 `空格`、`WASD`、`E/Q/F` 这些游戏动作键。

> 填错了也不会炸：`hotkeySafe` 开着时，`F12`/`F5`/`F3`/`F1`/`F6`/`F7`/`F10`/`F11` 会被自动换成安全键并打日志；
> 但「原神占用的键」脚本没法替你判断——那些键按下去游戏那边照样有反应。

想强行用回 F12：设置里关掉 **「热键避开浮窗内置浏览器的快捷键」**（`hotkeySafe`）。
但不建议——DevTools 还是会弹。

如果 DevTools 已经弹出来了，**点它的关闭按钮**，或者再按一次 `F12`。

### 默认值（v1.6.27 起：播放/暂停 = ~，其余仍留空）

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 缩放模式开关 | `Insert` | 按一下进入（拖动画面、拉四角改尺寸），再按一下退出 —— 见下面的「切走再回来」 |
| **播放/暂停** | **`~`** | 全局生效（游戏有焦点也管用）。v1.6.27 起从 F9 改成波浪号 —— 笔记本的 F9 常被亮度键占用，脚本收不到 |
| 登录窗开关 | `End` | 开/关 B 站登录窗（v1.6.5；登录窗全屏盖住画面，只能靠它关） |
| 其它动作热键 | 空 | 快退快进、透明度、隐藏、上/下集、打怪点……都要自己填 |

> 为什么是 F9：原神把 `F1`~`F8` 全占了（冒险之证 / 联机 / 祈愿 / 纪行 / 活动 / 设置 / 尘歌壶 / 星之归还），
> BGI 自己用 `F11`，浏览器抢 `F10` `F12` `F5` `F3` —— **只剩 F9 是干净的 F 键**。
> 详见上面「到底哪些键不冲突」。

#### 切走再回来：热键就是开/关，不猜焦点（v1.6.6 改回来）

去浏览器查个东西、按 `Win` 键看一眼别的事，回来的时候浮窗可能已经不在前台了。

**这条路上踩过两次坑，都记在这儿：**

- v1.6.3 做成"两段式"：浮窗失焦时按一下只把浮窗接回来，第二下才退出；
- v1.6.5 又加了一条"失焦 1.2 秒自动把鼠标还给游戏"的守卫。

两套都靠页面上报的 `document.hasFocus()` 判断"浮窗是不是被切走了"。可实测在 BGI 这个
WebView2 里，**`hasFocus()` 一直是 `false`**（页面从来没拿到过键盘焦点），于是：

- 守卫认为"你早就切走了"，**每次进缩放模式 1.2 秒后就把鼠标塞回游戏中心**；
- 两段式认为"你是从别处回来的"，退出要按两下。

所以 v1.6.6 把这两套全删了，规则回到最简单的一条：

| 当前状态 | 按一下缩放热键 |
| --- | --- |
| 缩放模式没开 | 进入（BGI 会 `SetForegroundWindow` + `Activate`，把前台和鼠标一起抢回浮窗） |
| 开着 | 退出，鼠标穿透给游戏 |

从别处回来时浮窗不归你操作，按键无非是"先退出、再进入"两下，顺序完全可预期，
不会再出现"鼠标自己跳回屏幕中心"。

**交还鼠标只有两条路**：按缩放热键退出，或者鼠标移开/空闲后自动穿透（v1.6.8 起"单击画面"那条已删除）。
两条都不碰播放状态。

旧版 BGI 没有这个 API 就安静跳过，不影响其它功能。

> 如果系统就是不让抢前台（`SetForegroundWindow` 被前台锁拒掉），连着按两下会直接退出——
> 这个热键任何时候都退得掉，不会卡住。

以前默认占着 `F1`~`F12`，结果 `F5` 一按就刷新页面、`F12` 一按就弹 DevTools，所以改成留空。

打怪点也可以直接用画面上的 `＋怪` 按钮（45 秒内有点 = 移动，Shift+点击 = 删除）。

#### 按住 Alt：临时接管鼠标（v1.6.14）

原神里**按住 Alt 就是"显示鼠标"**。脚本把同一颗键借过来用：按住 Alt 的这段时间浮窗收点击，
可以顺着光标拖进度条、点暂停/倍速/齿轮；**松开 250ms 后自动还给游戏**，播放状态不变。

- 不用先按 `Insert` 进缩放模式再退出来，点一下条就完事；
- 只在按住期间生效，不会长期挡住游戏点击；
- 想换成别的键：设置里 **「按住哪个键临时接管鼠标」**（`holdKey`），填 `Ctrl` 也行，
  填 `Ctrl,Alt` 两个都认，**留空就关掉**这套（老配置里的 `ctrlDrag` 复选框也还能用，会当成 Ctrl）；
- 正在拖进度条的瞬间松开 Alt 也不会被"抢回去"（脚本会等手松开拖拽再切）。

#### 方向键（v1.6.4，v1.6.14 起全局生效）

| 键 | 作用 |
| --- | --- |
| `←` / `→` | 后退 / 快进 5 秒。按住不放会连发（140ms 一次），等于连续快进 |
| `↑` / `↓` | 音量 +10% / -10%，到 0 显示「静音」 |

**不用先按缩放热键了**：v1.6.14 起方向键走主脚本的全局钩子，游戏有焦点时也管用
（原神本来就没绑方向键，不会跟走位打架）。钩子没起来时页面还留着一份自己的处理，等于兜底。

- 想关掉：设置里取消 **「方向键全局生效」**（`arrowGlobal`）；
- **注意 ↑↓ 和 BGI 撞车**：BGI 自己的「暂停任务 / 取消任务」默认就是 `↑` `↓`（`KeyboardMonitor`）。
  你一边跑一条龙一边按 ↑↓ 调音量，BGI 会跟着暂停/取消 —— 两个都留着就会"一键两用"，
  建议去 BGI 设置里把那两个键改掉或清空；
- 焦点在透明度滑块上时方向键归滑块，不去跳视频（该给控件就还给控件）。

> 顺便删掉了原来的「双击控制条吸附到下一个角」。那个手势太容易误触——
> 双击暂停键、双击画面任何地方都会把窗口扔到别的角落，很难受。

鼠标侧键填 `mouse4` / `mouse5`。只支持单键。

**在线模式改不了播放速度**——跨域控制不到播放器，跟登录无关。想变速用本地文件，或点播放器自带倍速。

## 十、常见问题

**Q：侧栏空的 / 没有合集**
没开「JS HTTP 权限」，或 mid 填错，或网络打不开 B 站。

**Q：分类里没有某个新地图（比如至冬）**
索引结果缓存 7 天，你的缓存可能是按旧规则建的。v1.6.8 起规则版本变了会自动重建一次；
也可以直接点分类视图的 **↻** 强制重建（约十几秒，后台跑，不影响播放）。

**Q：分类卡片是按视频数量排的吗？**
不是（v1.6.9 起）。顺序写死在 `main.js` 的 `REGION_ORDER`，**最新的地图永远第一**——
至冬只有 7 条也排在最前，不会因为数量少被挤到末尾。想出新的顺序，改那个数组即可。

**Q：弹幕一条都没有**
有些视频本身没弹幕；或者被 B 站风控。日志里会写「弹幕已加载 N 条」。

**Q：没有字幕 / 没有方向箭头**
1. 没填 SESSDATA；
2. 这个视频没有 AI 字幕（UP 没传、也没生成）；
3. SESSDATA 过期了。

**Q：在线一直黑屏**
1. 白名单换成 `"https://*/*"`；
2. 视频要求登录/大会员 → 在线模式看不了；
3. 看 BGI 日志里的 `播放器报告：…` 那几行，播放器会把真实报错抛上来。

**Q：热键没反应**
先确认是哪个键、有没有被别的程序占掉：

- **播放/暂停 `F9`** 是默认就绑好的，总开关默认开着；就算你把总开关关掉，这一颗仍然有效
  （关掉总开关只影响"其它动作键"）。按下去没反应就看日志里有没有 `热键 f9 → playPause`；
- 其它动作键都是**空的**，得在设置里自己填（填了才注册）；
- 日志会打「钩子收到按键「xxx」」，前 6 个未绑定的键都会打出来 —— 用这个确认键名写法
  （比如小键盘可能是 `numpad0` 而不是 `num0`）；
- 还是全无动静，可能是 `KeyMouseHook` 被安全软件拦了。

**Q：按 Win 键出去一趟回来，鼠标在屏幕中间，但点哪儿都进不了游戏**
按缩放热键（默认 `Insert`）退出缩放模式，鼠标立刻还给游戏（播放不变）。
v1.6.8 起**不再支持"单击画面还鼠标"** —— 那个手势误触太多，已经删了。

**Q：登录了 B 站，但退不出来，回不到游戏**
登录窗是铺满屏幕的独立窗口，会把浮窗整个盖住。**按 `End` 关掉**（也可以在设置里把 `hkLogin`
改成别的键）；忘了关的话 5 分钟后会自动关。关掉时会自动刷新视频，应用新的登录态。

## 十一、还差的一项：AI 导航（#2）

**妈宝这个功能是干嘛的**

它用模型从攻略视频里**猜出主播站在哪、朝哪边**，然后在你的屏幕上标出来。
你不用自己在脑子里把"视频里的位置"翻译成"我的位置"，照着走就不迷路。
注意它只是**指路**，不会替你跑；视频本身没有坐标数据，所以它只能"猜"。

**我能不能做？**

做到一模一样需要模型，做不到。更实在的替代是：**本地文件模式**下，把视频每一帧的小地图
和你的游戏小地图做模板匹配，直接算出真实相对位置「主播在你左前方 30 米」并画箭头——
**不是猜的，是量出来的**（这套匹配我在上一版脚本里验证过，位移误差 0 像素）。

但有两个前提，正好卡住你现在的情况：

1. **只有本地视频能做**（要读视频像素，在线 iframe 拿不到）；
2. 视频里必须**有原版小地图**，而且主播要落在你小地图范围内。

所以既然你不下载视频，这个替代就用不上。**建议先不做**——
字幕 + 方向箭头已经覆盖了大半「不迷路」的需求，真需要再说。

## 十二、已知限制

- 独占全屏不支持；
- **视频跳步自动暂停默认关**：判据只有"画面突变"，主播拉近/切镜头都会误停，还不太成熟；
- 在线只支持 B 站，无变速、480P、登录态不确定；
- 字幕依赖 SESSDATA 且视频要有 AI 字幕；
- 只支持单键热键；
- 侧栏依赖 UP 主的「合集/系列」结构（散装视频不会出现）；
- 收藏夹/肝度写在本地配置里，换机丢失。

## 十三、跟 BGI 自带功能共存（v1.6.29）

### 现象

朋友实测：开着浮窗，BGI 的「自动拾取」不捡东西、「自动剧情」卡在对话里。

### 先排除的两个错误猜测

1. **以为是抢焦点。** v1.6.23～v1.6.27 一直在打这条线（`scrubZone` 默认关、
   `startupInteractiveSec` 默认 0）。焦点确实会影响 BGI 的**前台**点击，
   但解释不了"一次都没成功过"——焦点问题是间歇性的。
2. **以为是浮窗挡住了截图。** 这条也有影响（见下文），但同样只影响被挡住的那块区域。

### 真正的根因

> 为了 JS 编写时的可配置性，你在实时触发里的所有配置都会在 JS 脚本运行前关闭，
> 你的实时触发将不会生效，除非 JS 作者在代码中开启对应配置。
> —— BetterGI 官方 FAQ「为什么不拾取/不吃药/不点剧情」

BGI 跑任何 JS 脚本前，会把它自己的实时触发（`TaskTriggerDispatcher` 里的那一堆）清空，
把画面识别能力让给脚本。所以自动拾取 / 自动剧情**根本没启动**，这不是"两个功能打架"，
是"另一个功能被关掉了"。

顺带解释了一个老现象：为什么把配置写进 `User\config.json` 也没用——
`autoPickConfig.enabled` 一直是 `true`，BGI 只是不清它、不读它，清的是内存里的触发器。

### 解法

`dispatcher.addTrigger()` 重新注册实时任务：

```js
dispatcher.addTrigger(new RealtimeTimer("AutoPick"));
dispatcher.addTrigger(new RealtimeTimer("AutoSkip"));
```

四个注意点：

| 注意点 | 原因 |
| --- | --- |
| 用 `addTrigger`，不用 `addTimer` | `addTimer` 会**清掉之前挂的所有任务**；`addTrigger` 只追加 |
| 只挂用户原本开着的 | 读 `User\config.json` 的 `autoPickConfig.enabled` / `autoSkipConfig.enabled`，关着的不强开 |
| 读不到配置要有降级 | 老版本 BGI、文件被锁、`LimitedFile` 路径受限都读不到；降级为"按设置面板勾选走"，并打一行 warn |
| 能力检测 | `typeof dispatcher === "undefined"` / 没有 `addTrigger` / 没有 `RealtimeTimer` 时只警告，绝不抛异常 |

代码在 `main.js` 的 `restoreBgiRealtimeTasks()`，调用点在 `setupHook()` 之后、
进主循环之前（窗口没建出来也不影响挂任务）。回归测试见 `_vp/test_bgitask.js`（26 项，
把函数抠出来喂假 BGI 环境跑：正常挂、按配置跳过、读不到配置降级、老版本兜底、`addTrigger` 报错）。

### 剩下的真实限制：截图遮挡

`AutoPick` / `AutoSkip` 都是**截图识别** + 模拟按键。BGI 的 GDI/BitBlt 截图是从桌面 DC 抓的，
叠在上面的浮窗会被一起截进去；浮窗正好压在「拾取提示」或「对话选项」上，那块就识别不出来。

两条出路：

- 把浮窗挪到画面边角（拾取提示在左侧中部、对话选项在底部中间）；
- BGI 启动页把截图方式换成 `WindowsGraphicsCapture`——它只截游戏窗口自身内容，不含置顶浮窗。

这条没法在脚本里自动解决：脚本拿不到 BGI 的当前截图帧，也不知道识别区的实时位置。
